## Résumé exécutif et note

**Lot privé avant correctifs : 6/10. Aptitude SaaS public multi-utilisateur : 2/10.** Ces notes sont des appréciations de maturité, pas des scores de conformité ou de sécurité mesurés.

La base est sérieuse : contrats stricts, idempotence, versions, revue humaine, accès privé et audit/outbox transactionnels. Deux protections de disponibilité interviennent toutefois après chargement intégral des données : corps HTTP entrant et réponse du moteur d'images. Des entrées limites provoquent également des HTTP 500 reproductibles. Les correctifs proposés couvrent ces problèmes, avec douze nouveaux tests.

Les comptes, invitations, quatre rôles demandés, facturation, calendrier et publication sont absents des chemins examinés. Ce sont des écarts à la cible commerciale ; ils ne constituent pas des vulnérabilités prouvées de l'atelier privé. **Aucune vulnérabilité critique confirmée.** L'acceptation complète du lot 1 reste conditionnée à la recette du SHA effectivement livré sur le PC.

## Contrôles de sécurité et spécifique éditorial

- Accès/IDOR : tenant présent dans les requêtes métier examinées ; tenant/acteur issus de la configuration serveur. Plusieurs refus inter-tenant testés en CI PostgreSQL. Aucun IDOR exploitable confirmé ; cela ne constitue pas un IAM multi-utilisateur.
- Sessions : cookie opaque, empreinte côté serveur, HttpOnly/SameSite Strict, Secure sur HTTPS ; huit heures, contrôle Origin et CSRF. Pas de révocation explicite de toutes les sessions lors d'une rotation du mot de passe dans le code examiné.
- SQL/XSS : requêtes paramétrées ; DOM construit avec textContent ; CSP restrictive. Pas d'éditeur HTML libre ni d'upload utilisateur dans les routes examinées : aucune sanitization WYSIWYG ou analyse antivirus à prétendre livrée.
- Secrets/chiffrement : contrôle borné décrit ci-dessus ; ni .env PC, secrets Actions, chiffrement disque ni sauvegardes inspectés. Le proxy HTTPS réel reste à tester.
- Intégrité/CI : Actions figées, permissions restreintes, reporting depuis main de confiance, activation soumise au SHA exact accepté. Pas de protection main supposée.
- Audit : mutation/audit/outbox atomiques, digest Slack limité aux métadonnées ; aucun message Slack envoyé pendant cette revue.
- SSRF : URL LLM configurée côté opérateur ; images limitées aux adresses locales/privées ; pas d'URL métier arbitraire constatée. Pas de SSRF prouvée.
- IA : sorties tronquées/JSON non conforme refusées, pas de relance ambiguë automatique. La consigne anti-injection ne garantit pas la véracité ; sources non vérifiées automatiquement. Aucun outil de publication autonome.
- Édition : expected_revision et verrou transactionnel, scénarios historiques conservés ; pas de fusion collaborative ou d'édition après approbation exposée.
- SEO : atelier privé sans pages éditoriales publiques ; sitemap/SEO de contenu hors périmètre actuel. Prévoir un site public séparé si nécessaire, sans rendre les créations privées indexables.
